# Wytyczne Infrastrukturalne Prometeusza (Docker & Hosting)

> **UWAGA DLA WSZYSTKICH AGENTÓW:**
> Pliki `Dockerfile` oraz `docker-compose.yml` w tym katalogu są **w pełni skonfigurowane, przetestowane i aktualne**.
> Służą one do hostowania Prometeusza jako autonomicznego kontenera poza piaskownicą deweloperską, bezpośrednio na serwerze hosta.
> Ścieżki hosta konfiguruje się w pliku `.env` (patrz `.env.example`).

---

## 1. Status Plików Docker
- **`Dockerfile`:** Jest kompletny. Używa dwuetapowego builda (Node 22 do zbudowania frontendu Vite + Python 3.12-slim dla backendu FastAPI). Nie modyfikuj go pod kątem lokalnego środowiska deweloperskiego `/workspace`.
- **`docker-compose.yml`:** Jest skonfigurowany pod architekturę hosta z wolumenami sparametryzowanymi przez zmienne środowiskowe:
  - Baza sesji / CLI: `${ANTIGRAVITY_CLI_HOST_DIR}` -> `/home/developer/.gemini/antigravity-cli:rw`
  - Binarka AGY: `${AGY_BIN_HOST_PATH}` -> `/usr/local/bin/agy:ro`
  - Przestrzeń robocza: `${WORKSPACE_HOST_DIR}` -> `/workspace:rw`
  - Port Web UI: `${PORT:-6767}:6767`
  - Flagi terminalowe: `stdin_open: true`, `tty: true` (wymagane dla PTY)

---

## 2. Zasady Wprowadzania Zmian (Konwencja)
Jeśli w przyszłości zajdzie absolutna konieczność modyfikacji plików Dockera (np. nowa zależność systemowa w Pythonie lub Node):
1. **ZACHOWAJ KONWENCJĘ ZEWNĘTRZNEGO HOSTA:** Nigdy nie zmieniaj ścieżek wolumenów na lokalne `/workspace`.
2. **KISS / YAGNI:** Nie dodawaj zbędnych usług, baz danych ani warstw abstrakcji – Prometeusz korzysta ze statycznego builda frontendu i lekkiego FastAPI.
3. **Multi-stage Build:** Frontend zawsze kompiluje się w pierwszym etapie (`frontend-builder`), a do etapu produkcyjnego trafia tylko skompilowany katalog `/dist`.
